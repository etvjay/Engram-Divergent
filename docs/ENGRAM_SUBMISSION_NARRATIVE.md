# Engram Submission Narrative

## Opening

Most memory systems help agents remember information.

Engram helps agents remember consequences.

The question is not whether an agent can retrieve what happened. The question is whether what happened changes what the next agent does, and whether the result changes what the system remembers afterward.

Engram converts execution consequences into persistent, scoped experience. It decides when that experience applies, what it is allowed to change, whether the change helped, and what the next agent should inherit.

## One argument across three use cases

The provider limitation is part of the evidence story, not hidden.

### Tool recovery

Tool A fails under high load and exhausts its retry policy.

Engram forms and admits a scoped lesson. A fresh process recalls the lesson as a MemorySlice and receives an InfluenceGrant that permits tool selection, retry policy, and fallback policy while denying budget increases, new signers, new wallets, new assets, and new capabilities.

The comparable task changes to a bounded Tool B recovery strategy. An isolated empty Sibyl arm returns to Tool A and failure. The lesson is contextual rather than a permanent blacklist.

```text
Tool A failure
→ scoped recovery lesson
→ fresh-process MemorySlice
→ bounded Tool B fallback
→ later qualification
```

### Agent handoff

Agent A forms experience. Agent B receives a MemorySlice and InfluenceGrant, not raw history or authority. B acts and its result evaluates the memory. Agent C receives the current memory version rather than the obsolete version.

Agent B does not receive:

```text
raw history
credentials
mandate
signer authority
unrelated memories
```

Experience can become portable without authority becoming portable.

## Benchmark boundary

The local A0-A5 benchmark remains:

```text
A2-A0 = +1.90
A5-A2 = +0.02
```

These are `LOCAL_DETERMINISTIC_EVIDENCE`, not general causal uplift or independent stochastic replication.

## Closing

Agents repeatedly pay to learn the same execution lessons.

Engram turns those consequences into bounded experience that survives runtimes and agents. It decides when the experience applies, what it is allowed to change, whether that change helped, and what the next agent should inherit.

Memory for what agents do.
